## 迁入物与改写口径

来源是现行权威的内部规范（§0~§9 + 牌码文法 + 校验清单，已经过一轮逐条复审验证）。改写原则：

1. **去掉产品内部引用**：源码文件行号（如 `GameSession.kt:305`）、版本号叙事、app 内部行为描述——读者不需要装 app，也不需要读原始实现源码。
2. **保留全部规范性内容**：范围与命名、设计铁律、顶层结构、`majo` 段、载荷帧必需字段校验清单、解析策略与错误码、往返不变式、版本演进规则、整局多手容器（format 2）。天凤互操作段（源 §5）**不留在规范里**，独立成文至 [`interop/`](../interop/README.md)。
3. **口径中立化**：面向「生成方 / 消费方」陈述义务（如源文「服务端校验口径」改写为生成方校验义务），不预设任何特定实现。
4. **样例外置**：规范附录中的骨架示意样例，由 [`examples/`](../examples/README.md) 的真实导出物替换，规范内只引用路径。
